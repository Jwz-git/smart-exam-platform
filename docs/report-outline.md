### 关于「组内分工」

课程要求 2—4 人/组，本项目实际由一人完成。这是报告里唯一需要你自己决定怎么处理的地方，两种诚实的写法：

- **按实际写**：说明由一人承担后端、前端、数据库、测试、文档和演示全部工作，并用 [`plan.md` 第 5 节](../plan.md#5-单人执行方式)的串行推进方式和「以自动化测试、接口响应、截图、干净环境复现替代第二人复核」说明质量是如何保证的。
- **按角色拆分写**：把工作按角色（后端 / 前端 / 数据与测试 / 文档与演示）拆成条目并标注工时占比，说明这些角色由同一人先后承担。

不要虚构成员姓名——课程评价要点里有「科技诚信」，`log.md` 也留有逐日的真实开发记录，虚构的分工与记录对不上。

## 3. 技术选型

| 层次 | 选型 | 选它的理由（答辩会问） |
|---|---|---|
| 前端 | Vue 3.5 + TypeScript + Vite | 课程指定前后端分离与 Vue；TypeScript 让接口契约在编译期就能对齐，改后端字段时前端立刻报错 |
| 状态管理 | 模块级 `ref`（未引入 Pinia） | 需要共享的状态只有令牌和当前用户两项，引入一整套状态管理库不划算 |
| 路由 | 一个 `active` 字符串（未引入 vue-router） | 本期只有单层页面切换，没有嵌套路由和 URL 分享需求；少一个依赖也少一处需要解释的复杂度 |
| 后端 | Spring Boot 3.5 + Spring Security | 课程指定 Spring Boot；Security 提供成熟的 JWT 资源服务器与方法级鉴权 |
| 持久层 | Spring JDBC（`JdbcClient`，未用 JPA） | SQL 全部显式可见，便于在报告里逐条说明每个查询做了什么，也避免 N+1 之类隐式行为 |
| 数据库 | MySQL 8.4 LTS + Flyway | 课程指定；Flyway 让结构变更版本化，不依赖手工改表 |
| 鉴权 | 无状态 JWT（HS256，60 分钟） | 前后端分离下不需要服务端会话；代价是无法吊销，用「每次请求回查用户状态」补上停用即时生效 |

精确版本以 `backend/pom.xml` 和 `frontend/package-lock.json` 为准。

## 4. 关键设计决策（答辩问答素材）

每条都是「问题 → 做法 → 为什么不用另一种」，可以直接当答辩稿。

| # | 问题 | 做法 | 为什么 |
|---|---|---|---|
| 1 | 教师改了题库，历史成绩会不会变 | 组卷时把题干、选项、标准答案、解析快照写入 `paper_question` | 不快照的话，改一道题的答案会让已算出的分数失去依据。快照是成绩可追溯性的基础 |
| 2 | 学生连点两次「交卷」会不会重复计分 | 交卷与判分在同一事务内，先 `SELECT ... FOR UPDATE` 取行锁再读状态 | 顺序不能颠倒：先读后锁会让两个并发请求都读到「作答中」然后都去判分 |
| 3 | 一人一场怎么保证只有一份答卷 | `submission(exam_id, student_id)` 唯一约束 + 捕获约束冲突转 409 | 先查后插之间存在竞态，只有数据库约束能真正保证唯一 |
| 4 | 学生关掉浏览器，卷子怎么办 | 服务端每 30 秒扫描已过截止时间仍在作答的答卷，事务内自动交卷并判分 | 靠前端倒计时触发的话，关掉页面的答卷会永远停在「作答中」，教师也就永远无法完成阅卷 |
| 5 | 超时自动交卷判的是什么 | 答案在切题时和每 30 秒各同步一次到服务端 | 早期版本只在点交卷时提交答案，超时未交的学生被判 0 分——这是实际踩过的缺陷 |
| 6 | 刷新页面后答案从哪里恢复 | 服务端已保存答案优先，本地草稿只补服务端没有的题目 | 反过来会让过期草稿覆盖服务端答案，下一次同步就把旧答案写回去，造成真正的丢失 |
| 7 | 成绩公布前学生能看到什么 | 后端按「谁在看 + 是否已公布」裁剪字段，公布前分数、答案、解析、评语、名次一律 `null` | 前端不显示不等于没下发，浏览器里能看到的就等于已经泄露 |
| 8 | `0` 分和「不给你看」怎么区分 | 分数类字段用可空类型，`null` 表示不可见，`0` 表示真的 0 分 | 混在一起会让学生以为自己被判了 0 分 |
| 9 | 「已评分」怎么判断 | 看 `graded_at` 是否为空，不看分数是否为 0 | 教师完全可以给主观题打 0 分，那也是已评分 |
| 10 | 同分怎么排名 | 竞赛排名，同分并列且占用名次（`1、2、2、4`）；名次在 Java 里算而不用窗口函数 | Java 实现更直观也更易测；入选条件是「已交卷且无未评主观题」，全客观题的卷子交完即进排名 |
| 11 | 题目被引用了还能删吗 | 已被试卷引用的题目删除时降级为停用 | 物理删除会破坏历史试卷快照和成绩归属 |
| 12 | 账号停用后旧令牌还能用吗 | 每次鉴权都回查一次用户表，账号不存在或已停用即 401 | JWT 无法吊销；多这一次查询换来「停用真正生效」 |
| 13 | 换 AI 服务商要改代码吗 | 协议、地址、模型、密钥都是环境变量；适配层只做「拼请求、取文本」两件事 | 只改四个变量就能在 DeepSeek / 通义 / Kimi / 本地 Ollama / Anthropic 之间切换 |
| 14 | AI 会不会写出不合规的题 | 题型、难度、知识点、分值由教师指定；模型输出先归一化形态再走与手工出题完全相同的校验；不合规的丢弃并说明原因 | AI 只生成草稿，保存走普通的题目新增接口，不存在绕过校验的通道 |
| 15 | 时间为什么会差 8 小时 | 数据库连接强制 `connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true`，答卷开始时间由后端显式写入 | 由数据库生成的默认时间会按会话本地时区写入、按 UTC 读出，产生固定偏移——这是实际踩过的缺陷 |
| 16 | 统计页的平均分会不会和成绩页不一致 | 统计分析直接调用成绩接口的同一个实现，只自己算分布与逐题正确率 | 同一个数字有两处实现早晚会对不上；顺带「谁能看这场考试」的归属校验也只保留一处 |
| 17 | 主观题的正确率显示什么 | 显示 `—`，用 `null` 表示「不适用」，改看得分率 | 主观题没有对错。一道刚评了 8 分的简答题若显示「正确率 0%」，是直接的误导 |
| 18 | 为什么不用 ECharts 画图 | 用 CSS 条形图自绘，按最大值等比缩放 | 需要的只是一条横杠，为此加一个几百 KB 的依赖不划算——和不引入 vue-router、Pinia 是同一条标准 |
| 19 | 系统设置为什么不能改 | 只读展示当前生效的参数，配置一律来自后端环境变量 | 可编辑表单会造成「界面改完但进程没重启」的显示与生效不一致；把真实值显示出来才有价值 |

## 6. 「对程序运行结果的分析」素材

这是评价要点里明确列出的一条，写的时候不要只贴「测试全部通过」，要解释数字为什么是这个值。

- **客观题为什么是 20 分而不是 30 分**：单选答对得 10，多选**少选**得 0（规则是答案集合完全一致才得分，不给部分分），判断答对得 10，简答待批。少选不给分是刻意的——部分分需要额外的评分规则，而 MVP 选择了确定性最强的一种。
- **总分 28 = 20 + 8**：主观题评分后立即重算 `subjective_score` 与 `total_score`，两部分都已是一位小数，相加不引入新的精度问题。分值全程用 `DECIMAL(6,1)` 和 `BigDecimal`，不用浮点数。
- **排名为什么是 `1、2、2、4` 而不是 `1、2、2、3`**：竞赛排名下并列名次要占用位置。四份答卷 20 / 10 / 10 / 0 分，第三名的位置被并列的第二名占掉。
- **及格率 25.0% 怎么来的**：及格线取试卷总分的 60%（20 × 0.6 = 12），四份答卷只有 20 分那份达标，1/4 = 25.0%。及格线是通用取法，课程未规定，已在文档中写明。
- **平均分为什么只算已评完的答卷**：未批完的答卷主观题还是 0 分，计入会把平均分拉低，得出一个随阅卷进度变化的「假平均分」。
- **重复交卷为什么返回 409 而不是 200**：交卷是一次状态跃迁而非幂等写入，二次请求代表客户端状态与服务端不一致，用 409 让前端明确知道要刷新。数据库里始终只有一份答卷，可用 `SELECT COUNT(*)` 现场验证。
- **逐题正确率为什么单选 100%、多选 0%**：正确率的分母是已交卷答卷数，分子是满分人数。验收数据里学生甲单选答对（10/10，满分）、多选少选（0/10，非满分），因此两题的正确率分别是 100% 和 0%。多选没有部分分，这个 0% 反映的是评分规则而不是学生完全不会。
- **主观题的得分率 80% 怎么来的**：简答题满分 10 分、评了 8 分，8/10 = 80%。得分率在客观题和主观题上口径一致，因此可以跨题型比较难度；而正确率只对客观题有意义。
- **注释 37.0% 是保守值**：统计脚本只计整行注释，`code(); // 说明` 这类行尾注释不计入，因此真实注释密度高于该数字。

## 7. 心得体会素材

以下都是本项目真实发生过的事，改写成第一人称即可，比泛泛而谈「学会了团队协作」有说服力。

- **踩过的坑一：时区。** 答题倒计时莫名多出 8 小时。原因是 `submission.started_at` 用了数据库的 `CURRENT_TIMESTAMP` 默认值，按会话本地时区写入、按 UTC 读出。修法是连接串强制 UTC 会话时区，并让后端显式写入这个时间。教训是「时间由谁生成」必须是一个明确的设计决定，不能顺手交给数据库默认值。
- **踩过的坑二：超时自动交卷判了空白卷。** 早期只在点「交卷」时才提交答案，学生超时未交时后端拿到的是空白卷，直接判 0 分。修法是答案随时同步到服务端。教训是「兜底机制」本身也需要数据支撑，不能只有状态流转。
- **踩过的坑三：测试之间互相污染。** 加 AI 测试时用了 `@MockitoBean`，Spring 因此建了第二个应用上下文并重跑一次建表脚本；脚本只删了一张表，在「表已存在」处中断，后面所有测试都因为查不到账号而 401。修法是让建表脚本可重复执行。教训是共享的测试基础设施必须是幂等的。
- **一个反复出现的判断：安全边界要放在服务端。** 成绩公布前的字段裁剪、题目归属校验、评分上界、公布前置条件，全部在后端实现，前端的按钮禁用只作为体验优化。做界面时很容易图省事只在前端拦，但那等于没拦。
- **一个关于 AI 的判断：让 AI 只生成草稿。** 实现 AI 辅助出题时最省事的做法是让模型直接写库，但那样模型的输出就绕过了全部业务校验。最后的做法是「题型难度分值由人指定、模型只创作内容、输出必须过和手工出题相同的校验、保存走同一个接口」。AI 提高的是效率，不应该降低系统的确定性。
- **关于单人开发的质量保证。** 没有第二个人复核，就用自动化测试、接口响应、截图和干净环境复现形成多层证据。把「验收数据」写死进测试断言（20 分、28 分、`1、2、2、4`）尤其有效——任何改动动了判分逻辑，测试会立刻红掉。
- **关于工程取舍的诚实记录。** 令牌无法吊销、试卷时长目前只由前端约束、自动化测试只跑 H2 而非 Flyway，这些都是已知边界，写进了文档而不是藏起来。承认边界比声称「已全部实现」更接近工程实际。

## 8. 创新性可写的点

课程评价要点里有「是否具有创新性」。本项目的可写点偏工程实现而非功能新奇，如实写这几条：

1. **AI 辅助出题的双协议适配。** 同时支持 OpenAI 兼容协议和 Anthropic Messages 协议，换服务商只改四个环境变量。适配层刻意不发 `response_format: json_object`——OpenAI 和 DeepSeek 支持它，但 vLLM、Ollama 等本地服务未必认，改为提示词约束加解析端容错，兼容性更广。
2. **AI 输出的形态归一化 + 复用校验。** 把模型给的 `"AB"` 拆成 `["A","B"]`、`"正确"` 转 `true`、选项键统一大写，只改形态不改内容，正确性仍交给原有校验；部分草稿不合规时保留合规的并说明被丢弃的原因，而不是整批作废或静默少给。
3. **成绩可见性的字段级裁剪。** 同一个响应结构服务教师阅卷、学生答题回看、学生查分三个场景，按「谁在看 + 是否已公布」裁剪字段，并用 `null` 与 `0` 区分「不可见」与「真的 0 分」。
4. **服务端超时自动交卷。** 不依赖浏览器保持打开，配合答案随时同步，保证「关掉页面」和「正常交卷」得到同一个判分结果。
5. **快照式组卷。** 试卷保存题目快照，使题库可以自由修改而历史试卷、答卷和成绩完全不受影响。
6. **统计口径的单一实现。** 统计分析页不重算成绩：平均分、最高分、及格率和排名全部来自成绩接口的同一份实现，本模块只负责分桶与逐题聚合。同一个数字只有一处实现，两个页面就不可能对不上，归属校验也随之复用。
7. **零图表库的可视化。** 分布图用 CSS 条形图自绘并按最大值等比缩放，运行时依赖始终只有 Vue 一个（未引入 vue-router、Pinia、图表库和 UI 组件库），全部依赖都能在答辩时解释清楚为什么需要。

## 9. 思政报告（独立交付物）

课程要求单独一份思政报告，题目自拟，围绕科技报国、科技自立、创新精神、工匠精神、科技诚信展开。评分要点：

| 分数段 | 硬性门槛 |
|---|---|
| 90—100 | 字数 ≥ 2500，参考文献 ≥ 6 且相关性强 |
| 75—89 | 字数 ≥ 1500，参考文献 ≥ 3 |
| 60—74 | 字数 ≥ 1000，参考文献 ≥ 2 |

可与本项目结合的切入点：

- **科技自立**：技术栈全部选用开源自主可控的组件；AI 能力做成可替换的适配层，既能接国产模型服务，也能接本机部署的开源模型，不绑定单一境外服务商。
- **工匠精神**：注释比例、逐项验收证据、把验收数字写死进测试断言、如实记录已知边界而不是声称全部完成。
- **科技诚信**：不虚构团队成员和分工；未执行的验证如实写进「未覆盖范围」；不把竞品宣传数据当作本项目的性能依据。
- **创新精神**：AI 只做草稿、人工确认后入库这一边界设计——在引入新技术的同时不降低系统的确定性。
