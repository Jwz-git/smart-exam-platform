## 3. 最可能被追问的十三个问题

每条一句话回答，末列是[正文 3.6 关键设计决策](project-report.md#36-关键设计决策)里的编号，需要展开时翻那一行。

| 会被问 | 一句话回答 | 决策 |
|---|---|:--:|
| 一个人做的，凭什么相信质量 | 55+55 项自动化把验收数字（20、28、`1、2、2、4`）写死进断言，改坏判分立刻红；另有浏览器走查截图、真实 MySQL 复现、逐日记录四层证据 | 正文 1.3 / 8 |
| 教师改了题库，历史成绩会变吗 | 不会。组卷时把题干、选项、答案、解析快照写进 `paper_question` | 1 |
| 连点两次「交卷」会重复计分吗 | 不会。交卷与判分同事务，**先 `SELECT … FOR UPDATE` 取锁再读状态**；`(exam_id, student_id)` 唯一约束兜底，冲突转 409 | 2、3 |
| 学生关掉浏览器，卷子怎么办 | 服务端每 30 秒扫描过期仍在作答的答卷并事务内自动交卷；答案在切题时和每 30 秒各同步一次，所以兜底判的不是空白卷 | 4、5 |
| 成绩公布前学生能看到分数吗 | 看不到。后端按「谁在看 + 是否已公布」裁剪字段，`null` 表示不可见、`0` 表示真的 0 分 | 7、8 |
| 同分怎么排名 | 竞赛排名，并列占位：四份 20/10/10/0 得到 `1、2、2、4` | 10 |
| 换 AI 服务商要改代码吗 | 不改。协议、地址、模型、密钥都是环境变量，适配层只做「拼请求、取文本」 | 13 |
| AI 会不会写出不合规的题 | 不会入库。AI 只出草稿，教师确认后走普通新增接口，过与手工出题完全相同的校验 | 14 |
| 自动组卷为什么不直接把试卷存下来 | 只返回方案、不写库，保存仍走原组卷接口，因此「分值合计等于总分 / 题目属于本人 / 题目已启用」只有一处实现 | 25 |
| 多条规则会不会抽到同一道题 | 不会。按提交顺序依次抽并排除已抽中的；`(paper_id, question_id)` 上有唯一约束，重复必然保存失败，所以界面提示「先写条件窄的规则」 | 25—27 |
| 错题重练会改成绩吗 | 不会。练习记录写在独立的 `practice_attempt` 表；练习集刻意不下发标准答案，判分复用交卷时的同一个比较器 | 30—32 |
| 为什么不用 ECharts / vue-router / Pinia | 需要的只是一条横杠、一层页面切换和两个共享状态，自己实现比引依赖便宜；运行时依赖只有 Vue 一个，每个依赖都能解释为什么需要 | 正文 3.1 |
| 系统设置为什么只有六项能改 | 白名单标准是「改了立刻生效」，读取路径就是生效路径；密钥与连接串不能进浏览器，调度间隔与 HTTP 超时启动时已固化，开放编辑只会造成「界面改完但进程没变」 | 18、33 |

## 4. 汇报时容易踩的三个坑

- **报及格率必须连着及格线一起报。** 25.0% 的前提是及格线 60%（40 × 0.6 = 12 分）；管理员改成 50% 后同一场考试立刻变 75.0%。脱离前提这个数字没有意义。
- **多选题 0 分是评分规则，不是学生完全不会。** 规则是「答案集合完全一致才得分，不给部分分」，学生甲少选一项因此得 0；逐题正确率里的 0% 同理。
- **「测试全绿」不等于「可以交付」。** 11 个界面缺陷全部是自动化测试通过之后、在浏览器里走查才发现的——这句话本身就是心得体会里最实的一条。
