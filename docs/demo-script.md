# 演示脚本

验收现场照这份脚本从上到下点一遍，就是一次完整的「建题 → 组卷 → 发布 → 答题 → 交卷 → 阅卷 → 公布 → 查分」演示。每步都写了预期结果和对应的业务规则，被追问时可以直接答。

> 本脚本已于 **2026-09-04 在 Google Chrome 152 上完整走查一遍**，39 张截图存于 [`docs/images/screenshots/`](images/screenshots/)，逐项结果见 [`test-records.md` 第 6 节](test-records.md#6-真实环境走查记录2026-09-04)与[第 8 节](test-records.md#8-自动组卷试卷导出错题重练与可编辑设置实测记录2026-09-04)。脚本中的数字与自动化测试断言一致，也已在真实 MySQL 上复现。

## 0. 演示前准备

```bash
./scripts/init-local.sh                 # 首次：生成 .env、建库、装依赖
set -a && source .env && set +a
mvn -f backend/pom.xml spring-boot:run  # 终端 A
npm --prefix frontend run dev           # 终端 B
```

- 前端 `http://localhost:5173`，后端健康检查 `http://localhost:8080/api/health`。
- 演示账号：`admin` / `teacher` / `student`（学生甲）/ `student2`（学生乙）/ `student3` / `student4`，密码统一 `ExamDemo123!`。
- 建议开三个浏览器窗口（或用无痕窗口）分别登管理员、教师、学生，避免来回退出登录。

## 1. 管理员：账号管理（约 1 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1.1 | 用 `admin` 登录 | 进入管理员界面，侧栏只有首页、用户管理、系统设置 |
| 1.2 | 用户管理 → 查看列表 | 6 个演示账号 + 若干测试账号；无任何密码字段 |
| 1.3 | 按角色筛选「教师」 | 只剩教师账号 |
| 1.4 | 新增一个学生账号（密码 ≥ 8 位） | 提示新增成功，列表出现该账号且状态为启用 |
| 1.5 | 停用刚建的账号 | 二次确认后状态变为停用 |
| 1.6 | 尝试停用 `admin` 自己 | 按钮禁用；即使直接调接口也会返回 `400 CANNOT_DISABLE_SELF` |

**可讲的点：** 用户永不物理删除（存在答卷的账号删掉，历史成绩就失去归属），只允许停用；停用立即生效，此前签发的 JWT 在下一次请求就会被拒绝——代价是每次鉴权多一次用户表回查，换来的是「停用能真正生效」。

## 2. 教师：题库与组卷（约 4 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.1 | 用 `teacher` 登录 → 题库管理 | 深色侧栏 + 筛选卡 + 表格 + 分页 |
| 2.2 | 右上输入知识点名称（如「Java 基础」）→ 添加知识点 | 提示已添加，筛选下拉框出现该知识点 |
| 2.3 | 新增题目 ×4：单选、多选、判断、简答，每题建议分值 10 | 选择题在同一处编辑选项并勾选正确答案，勾中哪个就是标准答案 |
| 2.4 | 按题型 / 难度 / 知识点 / 关键词筛选 | 条件为「与」关系，命中数随条件收窄 |
| 2.5 | 停用一道题再启用 | 状态列在启用/停用间切换；停用题不能加入新试卷，历史试卷不受影响 |
| 2.6 | 组卷管理 → 从左侧勾选 4 道题移到右侧 | 逐题填分值，总分自动汇总为 40 |
| 2.7 | 保存试卷 → 发布试卷 | 状态从草稿变为已发布 |
| 2.8 | 考试管理 → 选刚发布的试卷，开放时间设为「现在 ~ 2 小时后」→ 创建草稿 → 发布 | 状态变为已发布，学生端立刻可见 |

**可讲的点：** 组卷时把题干、选项、标准答案、解析全部快照写进 `paper_question`。之后教师怎么改题库，已发布的试卷、已交的答卷和已算出的分数都不会变——这是成绩可追溯性的基础。「先草稿再发布」也不是多余的一步：考试一旦发布学生就能作答，而有答卷的考试不允许撤回。

### 2.9 批量导入题库（约 2 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.9.1 | 题库管理 → 导入题库 | 弹窗有「选择文件 / 下载模板 / 表格内容 / 填写说明」四块；此时**预览和确认导入都是灰的** |
| 2.9.2 | 点「下载模板」 | 下载 `题库导入模板.csv`，五行示例覆盖五种题型；模板由后端生成，表头就是解析器认得的列名 |
| 2.9.3 | 粘贴一份表格：2 行新题 + 1 行与题库重复 + 1 行题型故意写错 | — |
| 2.9.4 | 点「预览」 | 统计卡显示「数据行 4 / 可导入 2 / 跳过 1 / 失败 1」；逐行给出原文行号、结果和原因，失败原因标红；确认按钮变为**「确认导入 2 道」**并可点 |
| 2.9.5 | 点「确认导入」 | 提示「导入完成：成功 2 道，跳过 1 道，失败 1 道」；「可导入」变「已导入」；关掉弹窗后题库列表里出现这两道题 |
| 2.9.6 | 再点一次「确认导入」 | 按钮已禁用，同一批内容不能重复提交 |

**可讲的点：** 三处刻意的设计。① **默认只预览**：接口的 `dryRun` 缺省为 `true`，写库必须显式传 `false`——批量操作出错没法一键撤销，漏传参数的后果应该是「什么都没发生」。而且预览和导入是**同一段代码**，只差最后一步写不写库，所以预览说能导入几道，实际就是几道。② **导入没有绕过校验的通道**：题库现在有三条入口（手工、AI 草稿、批量导入），都收敛到同一个 `QuestionService.validateDraft`。演示时可以特意准备一行「标准答案写 C、但选项只有 A 和 B」——它格式完全合法，只有跑业务校验才拦得住；放过去就是一道永远判 0 分的题。③ **逐行独立成败**：导入服务刻意不加事务，每行由题目新增方法各自开事务，50 道里错 3 道只需要改这 3 道。另外知识点**不会自动创建**：名称是题库的分类骨架，表格里一个错别字就会留下一对永久的孪生分类，所以缺哪个就在结果里点名，教师在本页右上角就能补。

### 2.10 规则自动组卷（约 2 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.10.1 | 组卷管理 → 自动组卷 | 弹窗里已有一条默认规则（不限条件、抽 5 道、每道 10 分） |
| 2.10.2 | 第 1 条改成「单选题 / 不限 / 不限，抽 3 道，每道 10 分」，再「添加规则」写第 2 条「判断题，抽 2 道，每道 5 分」 | — |
| 2.10.3 | 点「生成方案」 | 统计卡显示「抽中题数 5 / 方案总分 40 / 规则条数 2」；规则表逐条给出条件、抽题数、**候选池大小**、每题分与小计；下方列出抽中的 5 道题 |
| 2.10.4 | 点「换一批」 | 题目换成另一组，规则和分值不变——服务端每次重新随机 |
| 2.10.5 | 点「应用到试卷 5 道」 | 弹窗关闭，右侧「试卷内容」被填入这 5 道题，总分自动汇总为 40；页面提示「自动组卷已加入 5 道题，确认后请点『保存草稿』」 |
| 2.10.6 | 微调（换掉一道、改一个分值）→ 保存草稿 → 发布 | 与手工组卷完全一样，走的是同一个保存接口 |
| 2.10.7 | 故意写一条「编程题 / 难，抽 30 道」 | 报错点名：「第 1 条规则（编程题 / 难）需要 30 道题，题库当前只有 2 道可用……」 |

**可讲的点：** 三处刻意的设计。① **只生成方案，不写库。** 保存仍走 `POST /api/v1/papers`，因此「分值合计等于总分」「题目属于本人」「题目处于启用状态」这些校验只有一处实现——这与「AI 只出草稿、保存走普通接口」「批量导入复用同一套校验」是同一条标准，题库和试卷都只有一条写入路径。② **抽题结果直接展示出来。** 抽题是随机的，如果预览和保存各抽一次，教师看到的方案就不是最终保存的那份。③ **题目不够时报错，不悄悄少抽。** 一份莫名少了 20 分的卷子比一句「题目不够」危险得多，教师很可能直接发布出去。另外每条规则都回报候选池大小：池子刚好等于抽题数时会标「无可换」，省得教师一直点「换一批」却发现题目没变。随机是在 Java 里用 `Collections.shuffle` 做的，不用 `ORDER BY RAND()`——既不绑定数据库方言，也才能同时算出候选池大小。

### 2.11 试卷导出（约 1 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.11.1 | 组卷管理 → 我的试卷 → 任一行的「导出」 | 弹窗默认「Markdown（可打印试卷）+ 不含答案」，并直接显示正文预览 |
| 2.11.2 | 看预览 | 卷头是总分 / 时长 / 题数 / 状态 / 导出时间；正文按大题分组（「一、单选题（本大题共 2 小题，每小题 10 分，共 20 分）」）；**没有任何答案与解析** |
| 2.11.3 | 勾上「含参考答案与解析」 | 正文立刻重新生成，卷末多出「## 参考答案与解析」，逐题给出答案和解析 |
| 2.11.4 | 格式切到「CSV（可回导题库）」 | 「含答案」开关变灰并锁定为勾选，旁边说明原因；预览变成带表头的 CSV |
| 2.11.5 | 点「下载文件」 | 下载 `<试卷名>.md` 或 `<试卷名>.csv` |
| 2.11.6 | （可选）把下载的 CSV 拿到「导入题库」里粘贴并预览 | 逐行都能解析并通过校验——导出与导入是配套的一对 |

**可讲的点：** 两种格式的用途完全不同，不是同一份内容的两种皮肤。**Markdown 是给人看的卷子**：不含答案时可以直接发给学生，因此「含答案」这个开关必须准确——一份本该发给学生的卷子带着答案，问题已经发生了，所以弹窗里直接把要下载的正文显示出来，改任何选项都立刻重新取一次。**CSV 是给系统看的交换文件**：列名与顺序完全等于题库导入模板，导出的文件可以原样喂回 `POST /api/v1/questions/import`，把一份历史试卷的题目搬进另一位教师的题库或另一套环境；导入要求「标准答案」必填，所以 CSV 必然含答案。导出内容取自**试卷快照**，与当时发布的卷子完全一致——只有难度、知识点和标签三列快照里没有，回查题库当前值，因为 CSV 的「知识点」是导入的必填列。

## 3. 学生甲：答题与交卷（约 3 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 3.1 | 用 `student` 登录 | 整页答题界面，没有侧栏；页签「考试列表 / 我的成绩」 |
| 3.2 | 找到刚发布的考试 → 进入考试 | 单题作答 + 右侧题号导航；顶栏显示剩余时间和「已答 n/N」 |
| 3.3 | 按验收数据作答：单选选对、多选**只选一项**（少选）、判断选对、简答随意填写 | 题号方块由灰变绿；切题时自动把答案同步到服务端 |
| 3.4 | **直接刷新浏览器**，再次进入考试 | 答案全部还在，倒计时起点不变——服务端回传了已保存答案 |
| 3.5 | 点交卷 → 确认 | 提示「客观题得分 **20** 分，简答题和编程题等待教师评阅」 |
| 3.6 | 再次尝试进入该考试 | 状态显示「已交卷」，进入按钮禁用；直接调接口返回 `409` |

**可讲的点：** 20 分 = 单选 10 + 多选 0（少选不得分）+ 判断 10。答案随时同步到服务端不是为了「自动保存」这个功能本身，而是为了让超时自动交卷有真实答案可判——早期版本只在点交卷时才提交答案，学生一旦超时未交，后端拿到的是一张空白卷直接判 0 分。恢复答案时服务端那一份优先、本地草稿只补服务端没有的题目，否则一次同步就会把旧答案写回去，造成真正的丢失。

### 3.7 超时自动交卷（可选，约 1 分钟）

创建一场结束时间在 1 分钟后的考试，让学生进入但不交卷。等待后端定时扫描（30 秒一轮），答卷状态会自动变为已交卷并完成客观题判分；此后再保存答案返回 `409`。**这条不依赖浏览器保持打开**——学生直接关掉页面也一样。

## 4. 教师：阅卷、公布与排名（约 3 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 4.1 | 成绩管理 → 选择刚才那场考试 | 统计卡显示答卷数 1、作答中 0、待批主观题 1 |
| 4.2 | 阅卷面板 → 点学生甲那行的「阅卷」 | 弹窗逐题显示题干、学生作答、标准答案、解析；客观题标注「系统自动判分」 |
| 4.3 | 给简答题填 8 分 + 一句评语 → 保存评分 | 弹窗顶部总分立刻变为 **28**；面板「待批」变为 0 |
| 4.4 | 尝试填 11 分 | 前端拦下并提示；即使直接调接口也返回 `400 SCORE_EXCEEDS_MAX` |
| 4.5 | 点公布成绩 → 确认 | 统计卡出现平均分、最高分、最低分、及格率；排名表出现名次 |
| 4.6 | 再点一次公布 | 返回 `409 INVALID_STATE_TRANSITION` |

**可讲的点：** 「是否已评分」看 `graded_at` 是否为空，不看分数是否为 0——主观题被判 0 分也是已评分。公布成绩有三个前置条件：至少一份答卷、无人仍在作答、全场主观题已批完；少任何一条，平均分和排名就会把半成品算进去。公布同时会关闭考试并冻结评分，没有撤回接口。

### 4.7 演示「未批完不能公布」（约 30 秒）

让学生乙也进入同一场考试但不交卷 → 点公布成绩，返回 `400 SUBMISSION_IN_PROGRESS`；让学生乙交卷但不批他的简答题 → 点公布，返回 `400 GRADING_NOT_FINISHED`。

## 5. 学生甲：查分与回看（约 1 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 5.1 | 学生窗口切到「我的成绩」页签 | 出现该场考试，总分 **28 / 40**，显示「第 1 名 / 共 1 人」 |
| 5.2 | 点「查看答卷」 | 逐题显示本人作答、标准答案、解析、逐题得分和教师评语 |
| 5.3 | 对照第 3 步 | 交卷后、公布前的那段时间里，这里看不到任何分数和答案 |

**可讲的点：** 裁剪在后端完成，不是前端不显示。公布前学生拿到的 `score`、`standardAnswer`、`gradingComment`、`rank` 一律是 `null`；用 `null` 而不是 `0` 表示「不给你看」，因为 `0` 表示「这题真的是 0 分」，两者不能混。

### 5.4 错题本与错题重练（约 2 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 5.4.1 | 学生窗口切到「错题本」页签 | 概况卡显示「错题总数 2 / 可重练（客观题）1 / 仅复习（主观题）1 / 已掌握 0」 |
| 5.4.2 | 看列表 | 多选题一行得分标红 `0 / 10`，状态「未掌握」；简答题一行是 `8 / 10`，状态「仅复习」——**未得满分就进错题本，不只是 0 分的题** |
| 5.4.3 | 点某行的「解析」 | 展开显示本人完整作答、参考答案、解析和教师评语 |
| 5.4.4 | 点「开始重练 1 道」 | 进入重练界面：只有客观题，**看不到标准答案，也看不到上次答错的选项**。若这道题已经练对过（状态显示「已掌握」），先取消勾选「只练还没练对的题」再点，否则按钮会因为「没有需要重练的题」而不可用 |
| 5.4.5 | 故意再答错一次 → 提交 | 结果页显示「答对 0 / 正确率 0%」，此时才给出参考答案与解析 |
| 5.4.6 | 点「再练一组」→ 这次答对 → 提交 | 正确率 100%；返回错题本后该题「练习次数 2」、状态变为「已掌握」 |
| 5.4.7 | 切到「我的成绩」核对 | 总分仍是 **28 / 40**，名次不变——**重练不改动任何成绩** |

**可讲的点：** 四条硬约束。① **只收录已公布成绩的考试。** 成绩公布前告诉学生「你这道错了」等于提前泄露成绩，也绕开了成绩接口精心做的字段裁剪。② **练习集刻意不下发标准答案。** 复习模式带答案和解析（成绩已公布，本人有权看），但重练模式的接口连上次的错误作答都不给——否则重练就退化成抄一遍答案，答案只在提交之后随判分结果返回。③ **判分复用交卷时的同一套规则**（多选必须集合完全一致），否则出现「考试判错、重练判对」时，学生完全无法理解哪个才算对。④ **重练不改成绩。** 练习记录写在独立的 `practice_attempt` 表，`submission` 与 `submission_answer` 一个字段都不碰；已公布的成绩不能被学生自己的练习改写。另外主观题只能复习：简答和编程题没有确定性判分规则，硬给一个「对 / 错」是假的。

## 6. 竞赛排名 `1、2、2、4`（可选，约 3 分钟）

需要四份不同分数的答卷，现场逐个登录较慢，建议二选一：

**方式 A（现场演示）** 另建一份只有 2 道客观题、总分 20 的试卷和考试，让 `student`、`student2`、`student3`、`student4` 分别答对两题 / 只答对第一题 / 只答对第二题 / 完全不答，得到 20、10、10、0 → 名次 `1、2、2、4`。全客观题交卷即出分，不需要阅卷。

**方式 B（出示自动化证据）** 直接运行并展示 `GradingFlowIntegrationTest.ranksTiedTotalsAsCompetitionRankingAndHidesOtherStudents`：断言里写死了名次 `1、2、2、4`、平均分 10.0、及格率 25.0。

**可讲的点：** 名次采用竞赛排名，同分并列且占用名次。排名入选条件是「已交卷」且「没有未评分的主观题」，而不是简单看答卷状态——全客观题的卷子交完就该进排名，不需要教师做任何事。

## 7. AI 辅助出题（约 2 分钟）

前提：`.env` 里配好 `AI_PROTOCOL` / `AI_BASE_URL` / `AI_MODEL` / `AI_API_KEY`（见 [README](../README.md#ai-辅助出题可选)）。没配也可以演示——会提示未配置，正好说明降级行为。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 7.1 | 题库管理 → AI 出题 | 弹窗里选知识点、题型、难度、数量、分值，可填补充要求 |
| 7.2 | 点生成草稿 | 显示协议与模型名、若干草稿；被丢弃的草稿会说明第几道、为什么 |
| 7.3 | 点某道草稿的「编辑并保存」 | 草稿填进普通的题目表单，标题为「确认 AI 草稿」 |
| 7.4 | 改几个字 → 保存 | 提示「AI 草稿已确认并保存到题库」，题库列表出现该题 |

**可讲的点：** 四件事是刻意这么设计的——① 题型、难度、知识点、分值由教师指定，模型只写题干、选项、答案和解析，因为这四项决定题目能否通过校验，交给模型只会凭空提高失败率；② 草稿不入库，保存走的是普通的 `POST /api/v1/questions`，AI 没有任何绕过校验的通道；③ 模型输出必须通过和手工出题完全相同的校验，不合规的丢弃并说明原因；④ 密钥只在后端环境变量里，换服务商（DeepSeek、通义、Kimi、本地 Ollama、Anthropic）只改四个变量，不改代码。

## 8. 统计分析与系统设置（约 3 分钟）

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 8.1 | 侧栏 → 统计分析 | 上方是题库概况与题型 / 难度 / 知识点三张分布图；计数为 0 的题型也在图上 |
| 8.2 | 选中刚才那场考试 | 出现答卷数、已评完、平均分、最高分、最低分、及格率，以及及格线「24 分（40 × 60%）」 |
| 8.3 | 看成绩分布 | 五个分段固定显示，28 / 40 = 70% 落在「70—79%」这一段 |
| 8.4 | 看逐题作答分析 | 单选正确率 100%、多选 0%、简答的正确率是「—」；正确率低于 60% 的题标红 |
| 8.5 | 侧栏 → 系统设置 | 上半部分是六项可修改参数（每项给出当前值、来源、默认值和说明），下半部分是只读的运行信息：Spring Boot / Java 版本、服务端时区、数据库产品与 Flyway 版本、令牌吊销策略、AI 配置状态 |
| 8.6 | 用 `admin` 登录 → 系统设置 → 把「及格线」从 60 改成 50 → 保存改动 | 提示「已更新 1 项设置，立即生效，无需重启」；该行来源变为绿色「已覆盖」，并记下修改人与时间 |
| 8.7 | 回到教师窗口刷新统计分析 | 及格线从「24 分（40 × 60%）」变为「20 分（40 × 50%）」，及格率随之重算——**没有重启后端** |
| 8.8 | 管理员点该行「恢复默认」 | 提示「已恢复默认值 60%」，来源回到「默认值」；教师端及格率也回到原值 |
| 8.9 | 试着把及格线填 120 → 保存 | 返回「『及格线』取值范围是 0—100%」，页面上的值不变 |
| 8.10 | 用 `teacher` 登录同一页 | 六项参数照样看得到，但**没有输入框、没有保存按钮**，右上写明「只有管理员可以修改」 |

**可讲的点：** 三处刻意的设计。① 统计里的平均分、及格率、排名**不是本页重算的**，而是直接调成绩接口的同一个实现——同一个数字有两处实现，早晚会对不上，顺带「谁能看这场考试」的归属校验也只有一处。② 主观题的正确率是 `—` 而不是 0%：主观题没有「对错」，一道刚评了 8 分的简答题若显示「正确率 0%」会直接误导教师，因此用 `null` 表示不适用，改看得分率。③ **系统设置只开放「改了立刻生效」的那几项。** 这一页原先是纯只读的，理由很实在：配置都来自环境变量，做成表单只会造成「界面改完但进程没变」。现在开放编辑靠的是把界限划清楚——可编辑的六项（及格线、令牌有效期、导入行数上限、导入是否判重、自动组卷抽题上限、错题重练每组题数）在每次用到时都会重新读取，读取路径就是生效路径；而数据库连接、JWT 与 AI 密钥不能出现在浏览器里，自动交卷间隔和 AI 超时在启动时就固化进了调度触发器与 HTTP 客户端，界面上改了不会生效，因此这些一律不进白名单。存储模型是「环境变量是默认值、数据库是覆盖层」，所以每一项都同时显示当前值、默认值和来源，「恢复默认」就是删掉覆盖行而不是写回一个当时的默认值。这一页仍然不含任何密钥，AI 密钥只以「已配置 / 未配置」体现。

图表是用 CSS 条形图自绘的，没有引入 ECharts 之类的图表库：本页需要的只是「按最大值等比缩放的一条横杠」，为此增加一个几百 KB 的依赖并不划算——这与项目里不引入 vue-router、不引入 Pinia 是同一条判断标准。

## 9. 异常与权限（约 2 分钟）

用浏览器开发者工具或 `curl` 现场发几个请求，比在界面上点更有说服力：

```bash
# 未登录 → 401 UNAUTHORIZED
curl -i http://localhost:8080/api/v1/questions

# 学生访问教师接口 → 403 FORBIDDEN
curl -i -H "Authorization: Bearer <学生令牌>" http://localhost:8080/api/v1/questions

# 非法分页 → 400 VALIDATION_ERROR
curl -i -H "Authorization: Bearer <教师令牌>" 'http://localhost:8080/api/v1/questions?page=0'

# 学生访问他人答卷 → 403 RESOURCE_FORBIDDEN
curl -i -H "Authorization: Bearer <学生乙令牌>" http://localhost:8080/api/v1/submissions/<学生甲答卷 ID>
```

**可讲的点：** 三层防护缺一不可——`SecurityConfig` 按 URL 前缀限角色、Controller 的 `@PreAuthorize` 收紧到具体方法、Service 再校验资源归属。前端隐藏按钮只是体验优化，不构成任何权限保证。
