## 1. 信息架构

| 角色 | 一级页面 | 核心操作 |
|---|---|---|
| 公共 | 登录 | 输入账号密码、查看失败原因 |
| 管理员 | 用户管理 | 查询、新增、禁用用户 |
| 教师 | 工作台、题库、试卷、考试、阅卷、成绩 | 建题、组卷、发布、阅卷、公布、统计 |
| 学生 | 可参加考试、答题页、我的成绩 | 进入考试、作答、交卷、查分 |

## 2. 核心页面草图

### 2.1 教师题库

```text
┌──────────────────────────────────────────────────────────┐
│ 题库管理                         [新增题目]               │
├──────────────────────────────────────────────────────────┤
│ 题型 [全部▼] 难度 [全部▼] 知识点 [全部▼] 关键词 [____] [查]│
├────┬──────────────┬──────┬────────┬──────┬───────────────┤
│ ID │ 题干摘要      │ 题型 │ 难度   │知识点│ 操作          │
│ 1  │ Java 中……    │ 单选 │ 中等   │ Java │ 编辑 停用     │
└────┴──────────────┴──────┴────────┴──────┴───────────────┘
```

新增/编辑题目根据题型切换答案控件；提交失败时保留输入并在字段附近显示原因。

### 2.2 教师组卷

```text
┌────────────────────题库候选────────────────┬────试卷内容────┐
│ 筛选条件                     [加入试卷]     │ 名称 [______] │
│ □ 单选题 A  □ 判断题 B  □ 简答题 C          │ 时长 [30] 分  │
│                                             │ 1. A [10分]   │
│                                             │ 2. B [10分]   │
│                                             │ 总分：20      │
│                                             │ [保存][预览]  │
└─────────────────────────────────────────────┴──────────────┘
```

发布前必须经过预览和完整性校验；总分由题目实际分值实时汇总，不允许用户单独填写一个不一致的总分。

### 2.3 学生答题

```text
┌──────────────────────────────────────────────────────────┐
│ Java 基础测试                   剩余 29:42    [交卷]      │
├──────────────┬───────────────────────────────────────────┤
│ 题号导航      │ 1. 以下说法正确的是？                     │
│ [1][2][3][4] │ ○ A  ○ B  ○ C  ○ D                       │
│ 已答 1/4      │                                           │
│              │ [上一题]                         [下一题] │
└──────────────┴───────────────────────────────────────────┘
```

交卷前二次确认并显示未答数量；倒计时归零后自动交卷。提交中禁用重复操作，服务端仍以事务和唯一约束兜底。

### 2.4 教师阅卷与学生成绩

教师阅卷页按学生和简答题展示“题干、学生答案、参考答案、满分、得分、评语”；所有主观题完成后才允许确认成绩。学生成绩页仅在公布后展示总分、各题得分和教师反馈。

## 3. 页面状态

每个列表和表单必须同时设计加载中、空数据、成功、字段错误、无权限和服务异常状态。考试页额外处理未开始、已截止、已提交、网络重试和服务端判定时间与浏览器倒计时不一致。

## 4. 原型评审标准

- 三类角色只能看到权限内入口。
- 教师能在不跳出主流程的情况下完成“建题—组卷—发布”。
- 学生能识别剩余时间、作答进度、未答题和交卷结果。
- 任何删除、发布、交卷、公布等不可轻易撤销操作都有明确确认。
- 页面状态能映射到 `docs/api.md` 中的成功与错误响应。
