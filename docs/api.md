# REST API 契约

本表同时包含已实现接口和已确认待实现接口；真实完成状态以 [`AGENTS.md`](../AGENTS.md) 为准。

## 1. 通用约定

- 基础路径：`/api/v1`；健康检查：`/api/health`。
- JSON 字段使用 `camelCase`；时间使用带时区的 ISO 8601 字符串；分值最多一位小数。
- 认证成功后使用 `Authorization: Bearer <token>`；登录接口除外。
- 分页参数为 `page`（从 1 开始）、`size`（默认 20，最大 100）；返回 `items`、`page`、`size`、`total`。

成功响应：

```json
{"data": {}, "requestId": "01J..."}
```

错误响应：

```json
{"code": "VALIDATION_ERROR", "message": "请求参数不合法", "fieldErrors": {"name": "不能为空"}, "requestId": "01J..."}
```

状态码：参数或非法业务状态 `400`，未登录 `401`，越权 `403`，资源不存在 `404`，唯一约束或状态冲突 `409`，未处理异常 `500`。

参数校验失败一律返回 `400 VALIDATION_ERROR`，包括请求体字段校验、查询参数范围（如 `page`、`size`）和无法转换的取值（如非法枚举）。未预期的异常返回 `500 INTERNAL_ERROR`，响应体使用同一结构，不包含堆栈信息。

## 3. 关键幂等与冲突规则

- JWT 访问令牌默认有效期为 60 分钟。退出接口返回 `204`，客户端必须删除令牌；当前 MVP 不维护令牌撤销名单，已签发令牌在过期前仍具备密码学有效性。

- 同一学生重复开始同一考试时返回现有未提交答卷；若已提交则返回 `409 SUBMISSION_ALREADY_SUBMITTED`。
- 重复交卷不再次计分，返回 `409 SUBMISSION_ALREADY_SUBMITTED`。
- 后端每 30 秒扫描一次已到截止时间且仍在答题的答卷，并在事务内自动交卷、判定客观题；该机制不依赖浏览器保持打开。
- 发布试卷、考试或成绩时状态不满足，返回 `409 INVALID_STATE_TRANSITION`。
- 前端不得依赖按钮隐藏实现权限；所有角色、资源归属和业务状态由后端再次校验。
- 成绩公布前，学生响应不得包含得分、标准答案、解析、评语或排名；公布后仍只能读取本人答卷。
- 排名只统计已评分的有效答卷，按总分降序采用 `1、2、2、4` 的竞赛排名。
- 公布成绩会同时关闭考试：状态变为 `RESULTS_PUBLISHED` 后学生无法再开始或继续作答，教师也不能再修改评分。该操作没有撤回接口。
- 学生的考试列表只返回 `PUBLISHED` 的考试，因此已公布成绩的考试不再出现在考试列表里，学生改从 `GET /api/v1/my/results` 查看。

## 4. 试卷、考试与答卷请求约定

- 创建试卷必须提交 `name`、`durationMinutes`、`totalScore` 和非空 `questions`；每项题目包含 `questionId`、`score`，分值合计必须严格等于总分。
- 创建考试必须引用本人已发布试卷，并提交 `name`、`paperId`、`startAt`、`endAt`；结束时间必须晚于开始时间且仍在未来。
- 保存答案使用 `{"answers":[{"paperQuestionId":1,"answerContent":["A"]}]}`；判断题答案为布尔值，简答题答案为字符串。
- 开始答卷接口写入的 `startedAt` 由后端生成并以 UTC 返回；前端答题倒计时取“考试结束时间”与“开始作答 + 试卷时长”中更早的一个。
- 开始答卷与查询答卷都会返回 `savedAnswers`（`paperQuestionId` 与 `answerContent` 两个字段），前端据此恢复答题界面。服务端这一份才是超时自动交卷实际判分的依据；浏览器本地草稿只用于补服务端没有收到的题目，不允许覆盖服务端已有答案。
- 试卷题目在创建时保存题干、选项、答案、解析和题型快照，之后修改题库不会改变历史试卷。

## 5. 题目答案约定

- 支持五种题型：单选题、多选题、判断题、简答题、编程题。
- 单选题和多选题必须至少包含两个唯一选项，标准答案为选项键 JSON 数组；单选题数组长度必须为 1。
- 判断题不包含选项，标准答案为 JSON 布尔值。
- 简答题和编程题不包含选项，标准答案为非空 JSON 字符串，只作为教师阅卷时的参考答案；两者都不参与客观题自动判分。
- `tags` 为可选的关键词标签，最长 200 字符，保存时按英文逗号规范化为 `a, b`；只用于列表展示和 `keyword` 检索，不参与判分。
- `keyword` 同时匹配题干和标签，`%` 与 `_` 按普通字符处理。
- `status` 取 `ACTIVE` 或 `DISABLED`；不传时返回全部状态，界面据此显示启用/停用并提供切换。
- 停用题目不能加入新试卷，但已引用它的历史试卷快照不受影响。
- 教师只能查询、查看、修改和删除自己创建的题目；删除已被试卷引用的题目时改为停用，保留历史数据。

## 6. 阅卷与成绩约定

- 只有简答题和编程题可以人工评分；对客观题调用评分接口返回 `400 NOT_SUBJECTIVE`，客观题分数只能由系统判定。
- 单题得分必须满足 `0 ≤ score ≤ 该题在本试卷中的分值`，超出返回 `400 SCORE_EXCEEDS_MAX`；最多一位小数。
- 评语可空，最长 1000 字符；空白评语按 `null` 存储。
- 「是否已评分」以 `gradedAt` 是否为空判断，不以分数是否为 0 判断——主观题被判 0 分也是已评分。
- 每次评分后立即重算该答卷的 `subjectiveScore` 与 `totalScore`（`totalScore = objectiveScore + subjectiveScore`）；该答卷的主观题全部评完时状态推进为 `GRADED`。
- 评分接口返回重算后的完整答卷详情，前端不需要再查一次。
- 未交卷的答卷不能评分，返回 `400 SUBMISSION_NOT_SUBMITTED`。
- 公布成绩的前置条件有三条，任一不满足返回 400：至少一份答卷（`NO_SUBMISSION`）、无人仍在作答（`SUBMISSION_IN_PROGRESS`）、全场主观题已批完（`GRADING_NOT_FINISHED`）。重复公布返回 `409 INVALID_STATE_TRANSITION`。
- 统计口径：`gradedCount`、`averageScore`、`highestScore`、`lowestScore`、`passRate` 只统计已评完的答卷；平均分与及格率保留一位小数；及格线为试卷总分的一个百分比，默认 60%，可在系统设置里修改并立即生效。没有有效答卷时这些字段为 `null`，不返回 0。
- 排名入选条件是「已交卷」且「没有未评分的主观题」，因此全客观题的答卷交卷后即进入排名，不需要教师操作。
- 学生成绩接口只返回本人 `rank` 与参与人数 `totalCount`，不返回其他学生的姓名或分数。

## 7. 用户管理约定

- 用户名 3–64 位，只允许字母、数字、下划线、点和减号；重复返回 `409 USERNAME_EXISTS`。
- 初始密码至少 8 位，由后端 BCrypt 哈希后存储；任何响应都不含密码或哈希字段。演示环境未强制复杂度，真实部署应当收紧。
- 只提供查询、新增、启用/停用；不提供删除、改密码和改角色。存在答卷的账号删除后成绩会失去归属，因此一律只停用。
- 不允许停用当前登录的管理员本人，返回 `400 CANNOT_DISABLE_SELF`。
- 停用立即生效：账号无法登录，此前签发的 JWT 也会在下一次请求时被拒绝（每次鉴权都回查用户状态）。

## 8. AI 草稿约定

- 请求字段：`knowledgePointId`、`type`、`difficulty` 必填，`count`（1–5，默认 1）、`suggestedScore`（默认 10）、`requirement`（≤500 字）可选。题型、难度、知识点和分值由教师指定而不是模型决定，模型只负责题干、选项、答案和解析。
- 响应为 `{protocol, model, drafts, warnings}`；`drafts` 的元素与题目新增请求体完全同构，教师确认后原样提交即可。
- 教师编辑并确认后，仍通过题目新增接口和现有业务校验保存；本接口不写库。
- 模型输出先做形态归一化（选项键转大写、`"AB"` 拆成 `["A","B"]`、`"正确"` 转 `true`），再走与手工出题完全相同的校验。不合规的草稿被丢弃并在 `warnings` 里说明原因，全部不合规时返回 `502 AI_DRAFT_INVALID`。
- 错误码：未配置密钥 `503 AI_NOT_CONFIGURED`；上游报错或超时 `502 AI_REQUEST_FAILED`；空内容 `502 AI_EMPTY_RESPONSE`；输出不是合法 JSON 或缺少 `questions` 数组 `502 AI_INVALID_JSON`。以上都不影响手工出题与考试主流程。
- 服务商可自定义：`AI_PROTOCOL`（`openai` 或 `anthropic`）、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 均为后端配置，密钥不下发浏览器。
- 协议差异只体现在适配层：OpenAI 兼容服务走 `POST {baseUrl}/chat/completions` 并读 `choices[0].message.content`；Anthropic 走 `POST {baseUrl}/v1/messages`、附 `anthropic-version` 头并读 `content[0].text`。
- 未配置密钥、超时、限流、空内容或非法 JSON 返回可读错误，不影响手工出题和考试主流程。

## 9. 题库批量导入约定

- 请求体是**表格文本**而不是 multipart 文件：`{content, dryRun}`。前端读完文件后按文本提交，因此「选文件」和「直接粘贴」走同一个接口、同一段服务端代码。`content` 上限 200 000 字符；单次数据行上限来自系统设置（默认 200 行）。
- **`dryRun` 缺省为 `true`。** 不传这个字段就是预览，写库必须显式传 `false`——漏传参数的后果应该是「什么都没发生」。
- 预览与导入是同一段代码，只差最后一步写不写库：同一个解析器、同一套业务校验、同一套判重。因此预览给出的可导入行数就是实际会写入的行数。
- 响应为 `{dryRun, total, imported, skipped, failed, rows}`。`rows` 的每一项是 `{line, outcome, stem, type, questionId, message}`：
  - `line` 是**原文行号（含表头行）**，与教师在 Excel 里看到的行号一致；带换行的引号字段会正确占用多行；
  - `outcome` 为 `IMPORTED`（预览时表示可导入）、`SKIPPED`（题干重复）、`FAILED`（校验不通过）；
  - `questionId` 只在真正写库后才有值。
- **逐行独立成败，不整批回滚。** 导入服务刻意不加事务，每行由题目新增方法各自开事务，因此第 7 行失败不会连累前 6 行。
- **导入的题目走与手工出题完全相同的校验**，没有任何绕过通道；形态归一化（`"AB"` 拆成 `["A","B"]`、`"正确"` 转 `true`、选项键转大写）与 AI 草稿共用同一段实现。
- **知识点必须已存在，不自动创建**：知识点名称全局唯一且是题库的分类骨架，表格里一个错别字会留下一对永久的孪生分类。缺哪个知识点会在该行的 `message` 里点名。
- 题干与题库中已有题目（限本教师）或与本次导入的前面几行重复时**跳过而不是失败**：把同一个文件导入两次是最常见的误操作，它既不是成功也不是错误。判重可以在系统设置里关掉（同一题干配不同选项是合法出题手法）。
- 表格格式：首行为表头，按列名匹配（大小写、空白和括号内的提示文字都会忽略），列顺序任意。必填列为 `题型`、`题干`、`知识点`、`标准答案`；`难度`（默认中等）、`分值`（默认 10）、`选项`、`解析`、`标签` 选填。分隔符按首行自动探测，支持逗号、制表符和分号；支持 UTF-8 BOM、引号内的分隔符与换行。
- 选项写在一格里用 `|` 分隔，如 `A. 甲|B. 乙|C. 丙|D. 丁`；不写选项号时按顺序补成 A、B、C……同一格里要么都带选项号，要么都不带。
- 整表级错误直接返回 `400`：`IMPORT_INVALID_FORMAT`（内容为空、只有表头、缺必填列）、`IMPORT_TOO_MANY_ROWS`（超过系统设置里的行数上限，默认 200 行）。单行错误不返回错误码，而是作为 `rows` 里的一条 `FAILED` 记录。

## 10. 统计分析约定

- 范围一律取自令牌里的当前教师，路径和查询参数都不接受「看谁的数据」：题库计数与题库列表使用同一个 `created_by` 条件，因此统计数字与题库列表永远一致。
- 题型和难度分布由服务端补齐计数为 0 的分组并固定顺序（题型五项、难度三项）。数据库 `GROUP BY` 只返回出现过的值，补 0 才能让教师看出「一道编程题都没有」这种覆盖缺口。
- 单场考试的 `averageScore`、`highestScore`、`lowestScore`、`passRate`、`gradedCount` 直接复用 `GET /api/v1/exams/{id}/results` 的实现，成绩管理页与统计分析页不存在两套数字；归属校验同样复用，不是自己的考试返回 `403 RESOURCE_FORBIDDEN`，考试不存在返回 `404 EXAM_NOT_FOUND`。
- `distribution` 固定返回五段，按占试卷满分的百分比划分：`0—59%（不及格）`、`60—69%`、`70—79%`、`80—89%`、`90—100%`。`ratio` 的分母是已评完的答卷数。
- `questions` 是逐题统计，口径按题型区分：
  - 客观题统计全部已交卷答卷（交卷事务里已判完分），`fullMarkCount` 即答对人数（多选不给部分分），`correctRate` = 满分人数 / 答卷数；
  - 主观题只统计已评分的答卷，`correctRate` 与 `fullMarkCount` 为 `null`（主观题没有对错），未评分的数量单独放在 `ungradedCount`；一份都没批时 `averageScore` 为 `null` 而不是 0。
- `blankCount` 是留空人数。SQL NULL、JSON 的 `null`、空字符串和空数组四种形态都算留空，它们来自不同的写入路径（保存答案写 NULL、自动判分补行写 `'null'`、学生清空输入或取消勾选写 `""`/`[]`）。

## 11. 规则自动组卷约定

- 请求体是 `{rules: [...]}`，每条规则为 `{type, difficulty, knowledgePointId, count, score}`。三个筛选维度都可为 `null`，表示「不限」；`count` 1—100，`score` 最多一位小数。最多 10 条规则。
- **本接口只生成方案，不写任何数据。** 响应里的题目由前端填进组卷页，保存仍走 `POST /api/v1/papers`。这样分值合计、题目归属和启用状态的校验只有一处实现，自动组卷不会成为绕过校验的旁路——与「AI 只出草稿、保存走普通接口」是同一条标准。
- 抽题结果直接返回具体题目（内嵌完整题目对象），而不是只回一个数量：抽题是随机的，如果预览和保存各抽一次，教师看到的方案就不是最终保存的那份。反复调用相当于「换一批」。
- 规则**按顺序**抽题，同一道题不会被两条规则重复抽中（试卷题目在数据库上有 `(paper_id, question_id)` 唯一约束）。因此先写条件窄的规则更符合预期。
- 只从**当前教师本人题库里 `ACTIVE` 状态**的题目中抽取：停用题目本来就不允许加入新试卷，出现在候选池里只会导致保存那一步才失败。
- **题目不够时报错，不悄悄少抽**：返回 `400 AUTO_COMPOSE_NOT_ENOUGH`，信息里点明是第几条规则、要几道、实际有几道、是否已排除前面规则抽走的题目。一份莫名少了 20 分的卷子比一句「题目不够」危险得多。
- 其他错误码：合计抽题数超过上限返回 `400 AUTO_COMPOSE_TOO_MANY`（上限来自系统设置，默认 50 道）；规则引用的知识点不存在返回 `400 KNOWLEDGE_POINT_NOT_FOUND`。
- 每条规则回报 `poolSize`（满足该规则且未被前面规则抽走的候选数）。它等于 `count` 时说明这条规则没有随机空间，换一批也是同一批题——这个信息比「抽了几道」更有用。
- 随机在 Java 里完成（`Collections.shuffle`），不使用 `ORDER BY RAND()`：既避免绑定数据库方言，也才能同时给出候选池大小。

## 12. 试卷导出约定

- `GET /api/v1/papers/{id}/export?format=md|csv&withAnswers=true|false`，响应是**纯文本文件**而不是统一的 `data` 包装（要被浏览器当附件下载）。文件名含中文，按 RFC 5987 编码在 `Content-Disposition` 的 `filename*` 里。
- 两种格式用途不同：
  - `md`（默认）——给人看的卷子。按大题分组、带中文序号与分值合计，分组算法与学生答题页一致。`withAnswers=false`（默认）时正文里**没有任何答案与解析**，可直接发给学生；`true` 时在卷末附「参考答案与解析」。
  - `csv`——给系统看的题目交换文件。列名与顺序**完全等于题库导入模板**，因此导出的文件可以原样喂给 `POST /api/v1/questions/import`，把一份试卷的题目搬到另一位教师的题库或另一套环境。导入要求「标准答案」必填，所以 CSV 必然含答案，`withAnswers` 对它不起作用。
- 内容取自**试卷快照**（题干、选项、答案、解析、分值），与当时发布的卷子完全一致，之后改题库不影响导出结果。只有难度、知识点和标签三列快照里没有，回查题库当前值——CSV 的「知识点」是导入必填列，没有它导出的文件就无法回灌。
- CSV 带 UTF-8 BOM，逗号、引号和换行按 RFC 4180 转义，与导入侧的解析器是配套的一对。
- 归属校验复用 `ExamService#paper`：不是本人的试卷返回 `403`，不存在返回 `404 PAPER_NOT_FOUND`，格式不支持返回 `400 EXPORT_FORMAT_UNSUPPORTED`。

## 13. 错题本与错题重练约定

- 三个接口都挂在 `/api/v1/my/**` 下，与「我的成绩」同一套约定：**路径里不带学生 ID**，范围一律取自令牌，因此不存在「把 URL 里的 ID 改成别人」这类越权。该前缀限定为学生，教师和管理员访问返回 `403`。
- **错题只来自已公布成绩（`RESULTS_PUBLISHED`）的考试。** 成绩公布前告诉学生「你这道错了」等于提前泄露成绩，也会绕开成绩接口的字段裁剪。
- 收录标准是**该题得分低于满分**，不是「得 0 分」：未作答、答错和主观题部分得分都会进错题本。`blank` 字段区分「没答」与「答错」，两者在复习时的含义完全不同。
- **错题本（复习）与练习集（重做）下发的字段刻意不同**：
  - `GET /my/wrong-questions` 带 `standardAnswer`、`explanation`、`gradingComment` 和本人当时的作答，用于复习；
  - `GET /my/wrong-questions/practice` **不含标准答案、解析，也不含上次的错误作答**，否则重练就退化成抄一遍答案。答案只在提交之后随判分结果返回。
- 练习集只包含**客观题**：简答题和编程题没有确定性判分规则，只能对照参考答案自行复习，对它们调用提交接口返回 `400 PRACTICE_NOT_OBJECTIVE`。
- 练习集默认只取「最近一次还没练对」的题目（`onlyUnmastered=true`），按练习次数少的优先；`size` 缺省并且不能超过系统设置里的「错题重练每组题数」。没有可练的题时返回 `400 PRACTICE_NO_QUESTION` 并说明原因。
- 提交时每道题都要先确认「确实是本人已公布考试里的错题」，否则返回 `404 WRONG_QUESTION_NOT_FOUND`。这一步不能省：提交的响应**包含标准答案与解析**，少了它任何学生都能拿一个任意题目 ID 换到答案。同一道题重复提交返回 `400 DUPLICATE_ANSWER`。
- 判分复用交卷时的同一套客观题比较规则（多选必须集合完全一致，不给部分分），避免出现「考试判错、重练判对」这种无法向学生解释的分歧。
- **重练不改动任何成绩。** 练习记录写在独立的 `practice_attempt` 表，`submission` 与 `submission_answer` 一个字段都不动。已掌握的判据是「最近一次练习正确」；练对之后错题仍留在错题本里，只是标记为已掌握。

## 14. 系统设置约定

- 读接口教师与管理员都可访问，**写接口只有管理员**（URL 规则放行到两种角色，方法级注解再把写操作收紧到管理员）。
- 响应分六部分：`editable`（可修改项列表）与只读的 `runtime`、`security`、`exam`、`ai`、`database`。
- **可编辑项是一份白名单**（后端 `SettingsCatalog`），当前六项：及格线百分比、令牌有效期、单次导入行数上限、导入是否跳过重复题干、自动组卷抽题上限、错题重练每组题数。未列入白名单的键返回 `400 SETTING_UNKNOWN`。
- 白名单的入选标准只有一条：**改了立刻生效，且改错也不会让系统整体不可用**。因此下列参数刻意**不**开放：
  - 数据库连接与 JWT 签名密钥——改了系统整体不可用；
  - AI 密钥——绝不能出现在浏览器里；AI 地址与协议也不开放，否则「后端向哪个地址发请求」就变成了一个界面输入框；
  - 自动交卷扫描间隔与 AI 读超时——它们在启动时就固化进了 `@Scheduled` 触发器和 HTTP 客户端，界面上改了不会生效，那正是「显示值与生效值不一致」本身。
- 模型是「**环境变量是默认值，`system_setting` 表是覆盖层**」：读取时先看覆盖再退回默认。因此每一项都同时返回 `value`（当前生效值）、`defaultValue`（环境变量给的默认值）和 `overridden`（是否被覆盖），以及最后一次的修改人与修改时间。
- 写请求体是 `{values: {key: value}}`，只需提交要改的键。**值为空串表示恢复默认**——删掉覆盖行、之后跟随环境变量，而不是写回一个当时的默认值。
- **整批校验后再写库**：一次提交里有一项越界（`400 SETTING_INVALID`，信息里给出范围），则一项都不生效，不会留下「改了一半」的状态。返回 `{changed, settings}`，`changed` 是实际发生变化的项数（提交了但值没变的不计入）。
- **响应不包含任何密钥、密码或数据库连接串。** AI 密钥只以 `ai.configured` 这个布尔值体现「配了还是没配」。
- `database.schemaVersion` 是已成功应用的最高 Flyway 版本号；读不到迁移历史表时为 `null`（例如自动化测试用的 H2 手写 schema），不编造版本号。
- 角色限定为教师或管理员：匿名可访问的 `GET /api/health` 只回状态和时间戳，不返回版本与环境信息，避免给未登录者做信息收集。
