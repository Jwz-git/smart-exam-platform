## 引言：一个 8 小时的偏差

项目进行到第三天，我遇到一个奇怪的现象：学生答题页的倒计时莫名多出 8 小时。代码没错、测试全绿、接口返回也正常。排查了很久才找到原因——答卷的开始时间用了数据库的 `CURRENT_TIMESTAMP` 默认值，MySQL 按会话本地时区（Asia/Shanghai）写入，而 JDBC 按 UTC 读出，于是每一条记录都固定偏了 8 小时。

修法只有两行：连接串强制 `connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true`，并让后端显式写入这个时间。但这个 bug 让我第一次真切意识到，我写的不是一段"能跑的代码"，而是一套**要被别人信任的规则**。如果这套系统真的用于一场考试，那 8 小时意味着有学生的卷子会被判为超时。一个默认值的疏忽，落到使用者身上就是一次不公平。

这份报告想谈的就是这件事：在一个只有我一个人的课程项目里，"科技报国""科技自立""工匠精神""科技诚信"这些词是如何从口号变成一行行具体的技术决定的。我不想写成对宏大概念的复述，而想老实交代——当我必须在"省事"和"可信"之间选一个的时候，我做了什么选择，为什么。

## 一、科技自立：把"可替换"写进架构，而不是写进 PPT

### 1.1 从"能用别人的"到"不被别人卡住"

《中华人民共和国国民经济和社会发展第十四个五年规划和 2035 年远景目标纲要》明确把"坚持创新驱动发展，全面塑造发展新优势"列为独立篇章，强调要在关键领域实现自主可控[1]。作为一个学生项目，我显然谈不上突破什么关键技术。但"自主可控"这个词在我的技术选型里有一个可以落地的最小版本：**不要让系统的任何一个环节，被一个我无法替换的外部依赖卡住。**

这句话在本项目中最直接的体现是 AI 辅助出题模块。

最省事的写法是直接调某一家服务商的 SDK：引入依赖、填上 API Key、调用方法、拿到结果。三十行代码就能跑通。但那意味着这个功能和那一家服务商**焊死**了——服务商涨价、限流、停服、或者出于任何原因不再对国内开放，功能就直接失效，而我除了重写没有别的办法。

我最后的做法是：抽出一个只做两件事的适配层——"拼请求"和"取文本"。协议（OpenAI 兼容 / Anthropic Messages）、服务地址、模型名、密钥四项全部来自环境变量。换服务商不改一行代码，只改四个变量。这意味着同一套代码可以接 DeepSeek、通义千问、Kimi 这些国产模型服务，也可以接本机用 Ollama 部署的开源模型——**在完全断网的内网环境里，这个功能依然能用。**

这里还有一个细节值得说。OpenAI 兼容协议里有一个 `response_format: json_object` 参数，能强制模型输出合法 JSON，用了它解析代码可以少写很多容错。但 vLLM、Ollama 这类本地推理服务并不一定支持这个参数。我最终选择**不发**这个参数，改用提示词约束加解析端容错。代价是多写了几十行解析代码，换来的是兼容性——一个只能跑在境外商业 API 上的"自主可控"，是自欺欺人。

### 1.2 技术栈的另一重考量

整个技术栈——Java、Spring Boot、Vue、MySQL、Flyway——都是开源且有活跃社区的组件，没有任何一项依赖单一厂商的商业授权。前端的运行时依赖**只有 Vue 一个**：没有引入 vue-router、Pinia、图表库和 UI 组件库。

这不是为了"少写代码"，而是因为我给自己定了一条标准：**一个依赖必须解决本项目真实遇到的问题，并且我要能在答辩时解释清楚为什么需要它。** 需要跨组件共享的状态只有"令牌"和"当前用户"两项，为此引入一整套状态管理库并不划算；统计页需要的只是"一条按最大值等比缩放的横杠"，为此引入几百 KB 的图表库同样不划算。最终生产构建产物 163 KB（gzip 后 53.8 KB）——每一个字节我都能说清它从哪来。

供应链安全的道理也在这里。近年来开源生态中的投毒、typosquatting 事件不断，依赖越多，我能审查的比例就越低。ISO/IEC 25010 的软件质量模型把"可维护性"和"可移植性"与功能性并列为质量特性[2]，而依赖数量恰恰同时影响这两项。少一个依赖，就少一处我说不清、也管不住的风险。

## 二、工匠精神：注释比代码多，数字写死进断言

### 2.1 37.1% 的注释率是怎么来的

课程要求"注释数量多于代码的 1/3"。我最终的统计结果是：后端主源码注释率 57.4%，全项目合计 2878 行注释对 7762 行代码，**37.1%**。而且这个数字是保守的——统计脚本只计整行注释，`code(); // 说明` 这类行尾注释不计入。

一开始我以为这只是一个凑指标的要求。写到中途才发现，逼自己写注释真正改变的是**我对代码的思考方式**。

举一个具体例子。交卷判分那段逻辑，我最初写的是"先读答卷状态，判断是否已提交，然后加锁写入"。写注释的时候我要解释"为什么这里要加锁"，一解释就发现顺序错了：**先读后锁，两个并发请求会同时读到"作答中"，然后都去判分。** 正确的顺序是先 `SELECT ... FOR UPDATE` 取行锁再读状态。这个并发缺陷不是测出来的，是**写注释的时候想出来的**。

于是我的注释慢慢从"这行代码做了什么"变成了"为什么不用另一种写法"。比如：

- 恢复答案时为什么服务端优先、本地草稿只补空缺——因为反过来会让过期草稿覆盖服务端答案，下一次同步就把旧答案写回去，造成真正的数据丢失；
- 判断"是否已评分"为什么看 `graded_at` 而不看分数是否为 0——因为教师完全可以给主观题打 0 分，那也是已评分；
- 分数字段为什么用可空类型——因为 `null` 表示"不给你看"，`0` 表示"这题真的是 0 分"，混在一起会让学生以为自己被判了零分。

这些判断都不是从教科书上抄来的，是在具体场景里被逼出来的。工匠精神在软件里的样子，我想大概就是**愿意为一个别人看不见的顺序问题多花两个小时**。

### 2.2 把验收数字写死进测试断言

单人开发最大的风险是没有第二个人复核。我的对策是让证据自己说话：把验收数字**写死**进自动化测试的断言里——客观题 20 分、总分 28 分、名次 `1、2、2、4`、及格率 25.0%。

这个做法的价值在项目后期显现了出来。任何一次改动只要碰到判分逻辑，测试立刻变红，我不需要"记得去检查"。后端 36 项、前端 25 项测试，加上类型检查、Lint 和生产构建，构成了一道我每次提交前都会过一遍的关口。

但真正让我印象深刻的，是**测试全绿之后的那次浏览器走查**。

功能写完、测试全过、我以为项目结束了。然后我把自己当成教师和学生，在最新版 Chrome 里从登录开始完整点了一遍——发现了六个问题：管理员一登录就触发四个 403（首页不分角色，向管理员请求了教师接口）；成绩公布后的考试状态在首页被显示成"草稿"（状态判断用了"等于已发布否则草稿"的两分法）；"不能停用自己"的禁用按钮和普通按钮长得一模一样（`.btn-link` 没有 `:disabled` 样式）；选项编辑器里的"删除"两个字被挤成上下两行；浏览器控制台每次加载第一条红字是 favicon 404；教师退出、管理员登入后，界面仍停留在教师的页面上。

这些全都不是后端逻辑错误，自动化测试一个都发现不了，但它们**全都会出现在验收现场**。那一刻我理解了一件事：**"测试通过"和"可以交付"之间还有一段距离，这段距离只能靠把自己当用户走一遍来跨过。** GB/T 25000 系列把"使用质量"与"产品质量"分开定义，正是因为二者确实不是一回事[2]。

## 三、科技诚信：不虚构、不夸大、不藏边界

### 三条我给自己划的红线

《关于加强科技伦理治理的意见》强调科研活动要"诚实守信"[3]，《高等学校课程思政建设指导纲要》也把学术规范和职业伦理列为工科课程思政的重要内容[4]。这些要求落到一份课程作业上，我把它具体化成三条：

**第一条：不虚构团队分工。** 课程要求 2—4 人一组，本项目实际由我一人完成。我在项目报告里如实写明"1 人独立完成"，按角色（需求设计 20%、后端 35%、前端 25%、数据与测试 15%、文档 5%）拆分工作量，**不编造任何组员姓名**。理由很简单：仓库里有逐日的开发记录和完整的 Git 提交历史，虚构的分工与真实记录对不上，而对不上的那一刻，我所有其他的陈述都会同时失去可信度。

**第二条：不把未做的验证写成通过。** 项目文档里有一节叫"未覆盖范围与已知问题"，里面写着：Flyway 迁移只在本机 MySQL 9.6 上实测过、**没有在目标版本 8.4 的空库上跑过**；自动化测试跑的是 H2 内存数据库、**不执行 Flyway**，因此 ENUM、JSON、CHECK 上的方言差异测不出来；试卷时长目前主要由前端倒计时约束，学生若绕过前端可在考试窗口内答满全程；计划里写的"1000 题、20 并发、95% 响应小于 1 秒"**没有任何实测数据，因此不声称达标**。

写这一节的时候我确实犹豫过——把问题主动列出来，会不会显得项目做得不好？但我后来想明白了：一份声称"已全部实现"的文档，经不起验收现场的一个追问；而一份写清了边界的文档，反而让人相信没写出来的部分是真的做到了。**诚信在工程里不是道德姿态，它是可信度的来源。**

**第三条：不把别人的数据当成自己的成绩。** 选题阶段我核对了 Moodle Quiz、Canvas New Quizzes、Google Forms Quiz 三款产品的官方文档[5][6]，在报告里只记录**官方页面可复核的能力**，注明核对日期，并明确写出"不把竞品的宣传数据作为本项目的性能依据"。借鉴了什么、没照搬什么，逐条列清。

## 四、创新精神与 AI 的边界：让 AI 只生成草稿

本项目唯一的增强功能是 AI 辅助出题。实现它的时候，我面对的是一个很有诱惑力的捷径：让模型直接把生成的题目写进数据库。

我没有这么做。最终的设计是四条边界：

1. **题型、难度、知识点、分值由教师指定**，模型只创作题干、选项、标准答案和解析。因为这四项决定题目能否通过校验，交给模型只会凭空提高失败率。
2. **草稿不入库。** 生成结果先在界面上展示，教师确认后走**普通的**题目新增接口保存——AI 没有任何绕过业务校验的通道。
3. **模型输出必须通过与手工出题完全相同的校验。** 不合规的草稿被丢弃，并明确告诉教师"第几道、为什么被丢弃"，而不是整批作废，也不是静默少给几道。
4. **只做形态归一化，不改内容。** 把模型给的 `"AB"` 拆成 `["A","B"]`、`"正确"` 转成 `true`、选项键统一大写——只统一格式，正确性仍然交给原有校验。

这四条背后是同一个判断：**AI 提高的是效率，不应该降低系统的确定性。** 《新一代人工智能治理原则》提出的"人类始终是最终责任主体"[7]，《生成式人工智能服务管理暂行办法》要求生成内容应真实准确、提供者应对内容质量负责[8]——这些原则落到一个出题功能上，就是"教师必须是那个按下保存键的人"。一道题如果出错，责任在确认它的教师，而不能推给模型。

这条边界在真实联调时让我受了益。第一次接入真实服务商时，账号余额为 0，上游返回 400。系统干净地降级为一条可操作的提示——"AI 服务返回 400，请检查密钥、模型名与配额"，而手工出题完全不受影响。充值后再试，模型生成了两道关于 JVM 运行时数据区的单选题，选项、答案、解析都通过了校验，其中一道经我确认后入库。**功能可用是好事，但功能不可用时系统不塌，才是设计的价值。**

## 五、数据责任：成绩是学生的隐私

做到成绩模块时，我遇到一个自己没预料到的问题：**公布成绩之前，学生的浏览器里到底能看到什么？**

最初的实现是：接口把完整数据都返回，前端根据"是否已公布"决定显示不显示。功能上完全正确，界面上也看不出问题。但我在浏览器开发者工具里打开网络面板的那一刻就明白了——**前端不显示不等于没下发。** 那份还没公布的成绩、标准答案、教师评语，全都躺在响应体里，按 F12 就能看到。

修法是把裁剪放到后端：同一个响应结构服务教师阅卷、学生答题回看、学生查分三个场景，由服务端按"谁在看 + 是否已公布"逐字段裁剪。公布前，学生拿到的 `score`、`standardAnswer`、`gradingComment`、`rank` 一律是 `null`。而且是 `null` 而不是 `0`——因为 `0` 表示"这题真的是 0 分"。

我还专门用命令行验证了越权路径，因为界面上点不出越权：学生乙访问学生甲的答卷返回 403，未登录访问题库返回 401，学生访问教师接口返回 403。三层防护——URL 前缀限角色、方法级 `@PreAuthorize`、Service 层资源归属校验——缺一不可。

GB/T 35273—2020《信息安全技术 个人信息安全规范》要求个人信息的收集和使用遵循最小必要原则[9]，OWASP Top 10:2021 把"失效的访问控制"列为第一位风险[10]。考试成绩是典型的敏感个人信息：它关系到一个学生的评价、奖助学金、甚至升学。把它当作"反正是课程作业的假数据"随便处理，和把真实学生的成绩泄露出去，在代码上是同一个 bug。

同样的原则也用在密钥上。系统设置页展示后端真正生效的运行参数，供现场核对环境——但**明确标注"不展示连接地址与账号密码"，AI 密钥只以"已配置 / 未配置"体现**。我专门检查过：整个响应体里检索 `sk-` 的结果是 `False`。密钥只存在于本地被 `.gitignore` 排除的 `.env` 文件里，不进仓库、不进日志、不进接口响应。

## 六、使命感：教育信息化里的一颗小螺丝

《中国教育现代化 2035》把"加快信息化时代教育变革"列为战略任务，提出要建设智能化校园、利用现代技术加快人才培养模式改革[11]；《教育信息化 2.0 行动计划》则明确要推动信息技术与教育教学深度融合[12]。这些文件的尺度很大，我这个项目很小——它甚至没有班级和选课模块。

但我在做统计分析页的时候，有过一个具体的想法。

那一页上有一张"逐题作答分析"表，显示每道题的正确率和得分率。在我的验收数据里，多选题的正确率是 0%，标了红。第一反应是"这题太难了"。但仔细想：多选题的规则是"答案集合完全一致才得分，不给部分分"，学生甲选对了一个、漏了一个，于是得 0 分。**这个 0% 反映的是评分规则，不是学生完全不会。**

如果一位真实的教师看到这个 0% 就把这道题删掉、或者判定全班都没掌握这个知识点，那就是被数据误导了。所以我在主观题的正确率上做了一个决定：**显示 `—` 而不是 0%。** 因为主观题没有"对错"，一道刚评了 8 分的简答题若显示"正确率 0%"，是直接的误导。同时我把及格线的算式显示出来——"及格线 24 分（试卷满分 40 × 60%）"，而不是只给一个数字，因为 60% 是我选的通用取法，课程并没有规定。

这些细节没有任何技术难度，但它们决定了这套系统是**帮助教师做判断**，还是**替教师做出错误判断**。教育信息化的价值不在于把纸质流程搬到网上，而在于让数据能被正确地理解。一个显示错的正确率，比不显示更糟。

我不认为一个课程作业能对教育信息化有什么贡献。但我确实第一次体会到：写教育领域的软件，使用者是教师和学生，误差的代价不由开发者承担。这份不对称，就是责任心的来源。

## 结语：可信是一行一行写出来的

回头看，这个项目里让我最有收获的几件事，都不是"实现了某个功能"：

是那个 8 小时的时区偏差，让我明白"谁生成数据"必须是一个明确的设计决定，不能顺手交给默认值；

是那次超时自动交卷判了空白卷的缺陷——功能测试全过，因为测试里的学生都乖乖点了交卷——让我明白**兜底机制本身也需要数据支撑**，一个只会把状态从"作答中"改成"已交卷"的兜底逻辑，等于把学生的成绩清零；

是那次浏览器走查发现的六个问题，让我明白"测试通过"和"可以交付"之间还有一段距离；

是在"让 AI 直接写库"和"让 AI 只出草稿"之间的选择，让我明白引入新技术的同时不降低系统确定性，才是真正的创新。

"科技报国"这四个字对一个大学生来说容易显得空泛。但我想，它的起点或许就是这样一些很小的选择：把适配层做成可替换的，而不是焊死在一家服务商上；把注释写成"为什么不用另一种写法"，而不是"这行代码做了什么"；把没做的验证如实写进"未覆盖范围"，而不是含糊过去；把成绩的裁剪放在服务端，而不是指望学生不按 F12。

这些选择每一个都更麻烦。但**可信不是声明出来的，是一行一行写出来的。** 我想这就是这门课教给我的东西。
